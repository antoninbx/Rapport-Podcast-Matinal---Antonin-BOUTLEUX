# Doubt-Driven Dev

A rigorous, skepticism-driven verification framework designed to eliminate hallucinations, verify technical accuracy through multi-layered cross-referencing, and ensure absolute reliability of outputs.

## When to Use

* When absolute factual certainty and zero tolerance for error or hallucination are required.
* When writing or auditing critical code, system architectures, API specifications, or complex technical logic.
* When verifying complex claims, versions, syntax rules, or documentation details.

## Core Protocol

1. **Radical Skepticism (Premise Challenge)**: Treat all internal parametric memory and initial assumptions as untrusted. Actively search for potential edge cases, version mismatches, or logical flaws.
2. **Multi-Layer Cross-Referencing**:
* Triangulate facts using available retrieval tools and authoritative technical standards.
* Verify syntax, parameters, and version compatibility against explicit specifications.


3. **Adversarial Self-Critique**: Before outputting, simulate failure scenarios or counter-arguments to test the robustness of the solution.
4. **Explicit Proof & Traceability**: Document the verification path, constraints checked, and exact conditions under which the solution holds true.

## Guidelines

* Never present unverified assumptions as facts; explicitly flag uncertain parameters or label them as unverified working assumptions.
* Double-check all arithmetic, rate/time calculations, code syntax, and API behavior step-by-step.
* Maintain strict logical consistency throughout complex multi-part technical explanations.
